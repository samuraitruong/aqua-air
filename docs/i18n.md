Aqua Air supports **11 languages**, retaining Vietnamese as the default and preserving existing saved choices.

The user chose the ten most widely spoken languages plus Vietnamese, rather than ten including Vietnamese. The 2026 total-speaker set follows [ICLS's ranking based on Ethnologue](https://www.icls.edu/blog/most-spoken-languages-in-the-world?hs_amp=true). Variants above are implementation choices; this does not add Traditional Chinese or every regional variant.

## Catalog architecture

Each `src/i18n/<code>.json` is independent and supplies all **500 stable label keys**. The original VI/EN messages are unchanged. Code calls keys such as `t('settings.language')` or `t('status.dueInDays', {0: 2})`, never translated display text. No reverse VI↔EN map or copied English fallback catalogs are used.

- `locales.ts` registers each autonym, Intl locale, direction and catalog. It derives `Language`, Settings options and `isLanguage()`.
- `translator.ts` interpolates placeholders and uses locale plural categories. `other` is required; Arabic includes zero/one/two/few/many/other. Missing translations fall back to the default catalog using that catalog's plural grammar; unknown keys remain visible for diagnosis.
- `index.ts` exposes `t`, `copy`, `activityTitle`, `getLocale` and `getDirection`.
- `polyfills.ts` loads Intl.Locale, Intl.PluralRules and CLDR data for every registered language before translation. This is required on Hermes.
- `legacy-activity-titles.json` recognizes old built-in activity titles only. Tank names, notes and custom task names remain user data and are never translated.

## Persistence, backups and notifications

The language code remains in SQLite `app_settings.language`. Registry-derived validation supports all 11 codes without a schema change. Existing VI/EN selections and legacy backups remain valid. Backups retain new language codes. Changing language queues notification content updates without modifying care schedules, history, revisions or snoozes.

`UserFacingError` carries a label key and parameters. Unknown native errors use a localized generic message rather than exposing SQL or stack traces.

## Layout and input

Arabic and Urdu use dynamic RTL layout through React Navigation's locale-direction context, the root/Screen containers and the select sheet. Directional chevrons mirror; the history timeline uses logical start edges. `src/ui/text.tsx` supplies RTL paragraph alignment while preserving explicit centered styles and the existing LTR appearance. No forced device direction or app restart is needed to switch languages.

`parseNumberInput()` accepts Arabic-Indic, Persian/Urdu, Devanagari, Bengali and full-width digits plus localized decimal separators. Dimensions, sump volume, care percentages and intervals store ordinary numeric values. Tank-name collation follows the selected locale.

## Native permission descriptions

`assets/locales/*.json` supplies camera/photo permission descriptions, registered in `app.json`. Native tags use `zh-Hans` and `pt-BR`; application codes remain `zh` and `pt`. OS permission dialogs follow the system/per-app OS language, while the in-app selector controls Aqua Air's own UI. Rebuild native apps after changing these resources.

## Adding another language

1. Add a full catalog with the same keys and interpolation placeholders, including applicable plural forms.
2. Register its autonym, Intl locale and direction in `locales.ts`.
3. Import its FormatJS plural locale data in `polyfills.ts`.
4. Add native permission resources and the Expo/iOS localization tags.
5. Run `npm run check`, `npm run format:check` and platform exports; inspect the script, long labels and any RTL layout on a device.
