# Aqua Air Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver the offline Vietnamese Aqua Air iOS/Android app covering the supplied twelve screens.

**Architecture:** Expo Router screens consume typed care services backed by SQLite. Calendar arithmetic, scheduling and backup validation are independent of native adapters. Native notification work follows durable revisions/outbox after data commits.

**Tech Stack:** Expo, TypeScript strict, React Native, SQLite, local notifications, local media, ZIP backups.

**Spec:** `docs/superpowers/specs/2026-10-28-aqua-air-design.md` and `Design/Aqua-Air-React-Native-Spec.md`.

## Global Constraints

- Four tabs: Tổng quan · Bể cá · Lịch · Cài đặt; all twelve supplied screen responsibilities.
- No backend/auth/analytics/cloud; production opens empty.
- Calendar dates YYYY-MM-DD; timestamps UTC; intervals 1–365; water percent integer 1–100.
- Photos relative to app documents; backup includes manifest, checksums, data and photos.
- Notifications: 48 pending, horizon 30 days, consumed catchup retained; no automatic care completion.
- No Git repository exists: work in the authorized workspace, keep progress in a ledger; do not invent commits.

## Review Focus

- Malformed and impossible dates must be rejected, including restored files.
- Editing a log's type must recompute both old and new schedules and clear stale overrides.
- Reopening after OS scheduling succeeds but DB recording fails must not duplicate jobs.
- Restore failures before commit must preserve both old data and old photos.
- Permission denial, cancelled picker and missing photos must leave core flows usable.
